# 프로토타입 구현 점검 (계획서 필수 8개 기능 기준)

2026-11-07 점검. 대상 커밋 `dbc2cd2` (Android 체험 앱 + 브라우저 미리보기).

## 요약

- 모든 기능은 **한 기기 안에서만 동작하는 체험 버전**입니다. 서버, 실제 내비(NaviHelper), 실제 위치(FusedLocation), Pleos 음성(STT/TTS)은 연결되지 않았습니다. 앱 화면에도 "가상 일행·체험"이라고 표시되어 있습니다.
- 필수 8개 중 **로컬 구현 2개**(모임 만들기, 목적지 정하기), **부분 구현 6개**입니다. 실제 서비스로 연결된 기능은 아직 없습니다.
- 규칙(상태 전이)은 꼼꼼하게 구현·테스트되었습니다. 경로 버전과 개별 수락, 변경 시 재수락, 전원 수락 후 출발, 호스트 권한, 종료·재실행 시 위치공유 해제, 주행 중 키보드 입력 차단이 여기에 해당합니다.

## 기능별 현황

| # | 필수 기능 | 상태 | 구현된 것 | 빠진 것 / 계획과 다른 점 |
|---|---|---|---|---|
| 1 | 모임 만들기 | 로컬 구현 | 크루·동행 선택, 이름 1~40자, 첫 목적지, 최대 5대 (`core/Trip.kt`) | 번개 없음(계획상 2단계와 일치). 모임 규모 5대 제한은 아직 결정되지 않은 "2~5대 vs 10대+" 문제를 2~5대로 정한 셈 |
| 2 | 초대·가입 | 부분 | 초대 코드 6자리 표시·복사 | 실제 가입 없음. 멤버는 "+ 가상 멤버" 버튼으로만 추가됨. 서버·인증 필요 |
| 3 | 목적지 정하기 | 로컬 구현 | 예시 장소 8곳에서 선택, 호스트만 변경, 변경 시 경로 버전 증가 | 실제 장소 검색(POI) 없음. 현재 목적지를 다시 골라도 버전이 올라가 전원 재수락이 필요해짐(사소함) |
| 4 | 경유지 추가 | 부분 | 최대 2개, 중복·목적지와 같은 장소 금지, 삭제 | **계획 규칙 "멤버 제안 → 호스트 승인" 흐름 없음**(호스트만 직접 추가). Android 지도 개념도(`RouteMapView.kt`)는 첫 번째 경유지만 그림 |
| 5 | 경로 동기화 | 부분(시뮬레이션) | 경로 버전, 멤버별 수락, 변경 시 재수락, 전원 수락 전 출발 차단, 내비 결과를 Simulated/Applied/Unavailable로 구분하는 `VehicleGateway` | `DemoVehicleGateway`는 항상 Simulated를 반환함. NaviHelper `requestRouteWithWaypoints` 연결 없음. 가상 멤버 수락은 버튼으로 일괄 처리 |
| 6 | 실시간 위치 지도 | 시뮬레이션 | 개념도에 멤버 아이콘 표시, 숨김·대략 위치 반영, 30초 넘은 위치 숨김 규칙(`visiblePosition`) | 실제 지도 없음. 아이콘 위치는 좌표가 아니라 화면에 고정된 자리이고, 게이트웨이 좌표는 표시 여부를 판단하는 데만 쓰임. 움직임·도착 예정 시간·이탈 표시 없음 |
| 7 | 위치공유 설정 | 부분 | 끄기 / 대략(소수 둘째 자리, 약 1km) / 정확. 기본 꺼짐, 종료·앱 재실행 시 자동 꺼짐, 저장 실패해도 숨김·종료는 즉시 반영 | 계획 기본값과 차이: 계획은 "모임 멤버에게, 시작~종료 동안 공유"인데 코드는 **기본 꺼짐(직접 켜야 함)**. **집 주변 숨기기, 이탈 알림(500m), 도착 시 자동 종료** 없음(현재는 호스트가 직접 종료) |
| 8 | 음성 메시지 | 부분 | Android 기본 음성 인식 → 확인 대화상자 → 기록. 받는 사람(전체/개별) 선택. 빠른 메시지 2종. 한국어 TTS 켜기/끄기 | 실제 전송 없음. **받은 메시지 읽어주기 없음**(TTS가 내가 보낸 문장을 다시 읽음, 가상 멤버는 메시지를 보내지 않음). 요구사항의 "지도 아이콘·차량을 눌러 받는 사람 선택"이 아니라 목록 대화상자. Pleos STT/TTS 미연결 |

확장 기능(음성 전화, 웰컴 라이트)은 손대지 않았습니다(계획과 일치).

## 검증 결과 (이번 점검)

- `scripts/test-core.sh`: 도메인 테스트 14개 통과. Linux, OpenJDK 21, Gradle 8.14.3에 들어 있는 Kotlin 2.0.21 사용.
  `CAMARADE_GRADLE_LIB=/opt/gradle/lib CAMARADE_JAVA=/usr/bin/java bash scripts/test-core.sh`
- `preview/index.html`: 브라우저(Chromium)에서 오류 없이 로드됨.
- Android Gradle 빌드 성공, lint 오류 0개(경고 9개). 에뮬레이터 실행은 아직 못 함. 자세한 내용은 `docs/sdk-verification.md`.
- (추가, 같은 날) Pleos Connect v2.1.0 에뮬레이터에서 앱 실행 확인. SDK 점검 화면으로 NaviHelper(경로+경유지 적용, 현재 위치), Vehicle(기어), FusedLocation, TTS가 실제로 응답함을 확인. STT는 초기화까지만 확인. `docs/sdk-verification.md`의 "에뮬레이터 실행 결과" 참고.
- (추가) 주행 상태 시험 결과, **현재 메인 앱은 차가 움직이면 Pleos가 "주행 중에는 사용할 수 없습니다"로 가립니다.** 주행 화면을 쓰려면 `distractionOptimized` 선언과 Pleos 심사 확인이 필요합니다. 또 Pleos 설정은 주행 중에도 키보드를 금지하지 않으므로 앱 자체의 키보드 차단이 계속 필요합니다. 도착 이벤트는 에뮬레이터에서 만들 수 없어 "도착 시 자동 종료" 시연은 앱 내 시뮬레이션이 필요합니다. 자세한 내용은 `docs/sdk-verification.md`의 "추가 확인".

## 인수인계 문서와 달라진 점 (팀원 조사 `docs/contest-and-sdk.md`)

- NaviHelper 경유지 최대 2개는 공식 문서(waypoint-settings)로 확인됨. 인수인계 문서에서는 "이름 기준 추정"이었음.
- **공식 문서로 확인함: Vehicle State·NaviHelper만 사용 가능하고, FusedLocation·STT·TTS·Vehicle Control은 "준비 중"입니다.** 위치·음성·앰비언트 라이트를 전제로 한 기획은 위험합니다(`docs/sdk-verification.md`).
- 공모전 평가 기준: 차량특화성·창의성·기술 활용성·사업성. 기획서(접수양식)가 필수이고, 시연 영상 또는 GitHub(소스+APK)은 선택 가산점이며, 2차 PT 전에 실제로 동작하는 앱이 필요합니다.

## 그 밖에 발견한 것

- `scripts/build-demo.sh`, `scripts/test-core.sh`의 기본 경로가 팀원 개인 Mac 경로(`/Users/...`)로 되어 있음. 다른 기기에서는 환경변수를 지정해야 실행되고, 저장소를 공개하면 개인 계정 이름이 노출됨.
- 패키지·applicationId가 `ai.camarade.app(.demo)`. 브랜드 철자(Carmarade)와 다르고 `camarade.ai` 도메인을 전제로 한 이름임. 마켓에 등록한 뒤에는 applicationId를 바꿀 수 없으므로 release 전에 확정해야 함.
- `apk/carmarade-demo.apk`는 테스트 키로 서명된 체험용입니다. 최종 제출에는 release 서명 APK가 필요합니다.
- `docs/superpowers/plans/`는 AI 작업 도구가 남긴 계획 파일이라 제출 저장소에 둘지 정해야 함.

## 우선순위 제안

**11.14 기획서 제출 전 (시연 영상에 보이는 것 위주, 로컬로 충분)**
1. 경유지 "멤버 제안 → 호스트 승인" 흐름 추가(계획 규칙과 맞춤).
2. 가상 멤버가 보낸 메시지를 TTS로 읽어주는 장면(음성 커뮤니티 핵심 장면).
3. 지도 개념도에서 아이콘을 눌러 받는 사람 선택, 경유지 2개 모두 표시.
4. 도착 시 자동 종료, 이탈 알림(시뮬레이션)과 위치공유 기본값 결정 반영.

**2차 PT(12.03) 전**
5. Pleos 프로젝트 생성 후 SDK 사용 가능 상태 확인 → `VehicleGateway`에 NaviHelper 연결(가장 확실한 차량특화 기능).
6. 최소 서버: 초대 가입, 멤버 위치·메시지 중계, 차량 간 거리 계산(이탈 판단).
7. 실제 지도 표시 방법 결정(Pleos 지도 UI 제공 여부 확인).
8. Gradle 빌드·lint·Pleos 에뮬레이터 실행 검증, release 서명.

## 결정이 필요한 것

- 위치공유 기본값: 현재 코드(기본 꺼짐) vs 계획서(모임 중 멤버에게 공유). 개인정보 측면에서는 현재 코드가 더 안전하지만 첫 사용 흐름이 한 단계 늘어남.
- 모임 규모: 코드는 5대로 고정되어 있음.
- applicationId·패키지 이름 확정.
